# 現場収支

小規模な工務店・大工向けの、**現場別の請求・入金・仕入・支払い管理Webアプリ**です。

元請・施主への請求と、材料屋・職人への支払いを現場ごとにまとめ、**いつ入って、いつ出ていくか**を確認できます。日本語UI・スマホ優先のレイアウトで、1つの管理用パスワードで利用します。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 現場台帳 | 現場名、取引先、進行中／完工、契約金額、メモを管理 |
| 取引先マスタ | 請求先・支払先、締め日、支払条件、メモを管理 |
| 請求管理 | 現場別に明細、税率、請求日、入金予定日を登録 |
| 入金管理 | 請求に対する分割入金、未入金・期日超過の確認 |
| 仕入・支払い管理 | 現場に紐づく仕入請求、支払期日、支払い記録を管理 |
| 現場別収支 | 売上・原価・差額を現場ごとに表示 |
| 資金繰り | 週別・月別の入金予定、支払い予定、差し引きを表示 |
| CSV出力 | 指定期間の記録をExcelで開けるBOM付きUTF-8で出力 |

データはPostgreSQLに保存します。入力にはプルダウン、日付入力、直前に選択した値の再利用を利用し、削除時には確認を表示します。

### 金額・税率

- 金額はすべて整数の日本円です。
- 明細ごとに消費税率 **10%／8%** を選択でき、1つの請求内で混在できます。
- 明細の税抜額は「数量 × 単価」、消費税は明細単位で1円に四捨五入します。
- 入金額・支払額から残額と状態を計算します。

### CSVの形式

列順は以下のとおりです。

```text
日付,取引先,現場,摘要,税抜,消費税,税込,区分
```

**請求・入金・仕入請求・支払いを、それぞれ独立した行として出力します。** 摘要で記録の種類を区別し、区分は「売上／仕入」です。

請求と入金、仕入請求と支払いが両方含まれるため、**全行の金額を単純合計しても売上・原価の合計にはなりません**。分割入金・分割払いの税額は元の記録から按分し、端数を調整します。

## 使い始める手順

1. 管理用パスワードでログインします。
2. 請求先・支払先を「取引先」に登録します。
3. 「現場」に現場名と取引先を登録します。
4. 現場に紐づけて請求・仕入請求を入力します。
5. 実際の入金・支払いがあったら、その記録を登録します。
6. 現場別収支と資金繰りを確認します。

## 技術構成

- **フロントエンド**：React、TypeScript、Vite、Tailwind CSS
- **画面・通信**：Wouter、TanStack Query、OpenAPIから生成したAPIクライアント
- **API**：Node.js、Express、Zod
- **データベース**：PostgreSQL、Drizzle ORM
- **API定義・コード生成**：OpenAPI、Orval
- **パッケージ管理**：pnpm workspaces

## 開発環境の準備

現在の開発環境は **Node.js 24・pnpm 10** です。別途PostgreSQLが必要です。

```bash
pnpm install --frozen-lockfile
```

### 環境変数・シークレット

| 名前 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL接続先 |
| `SESSION_SECRET` | セッション署名用の、十分に長いランダムな秘密文字列 |
| `ADMIN_PASSWORD` | 管理用ログインパスワード（10文字以上） |
| `PORT` | 各サービスの待受ポート |
| `BASE_PATH` | Webアプリの配信パス。ルート配信の場合は `/` |
| `NODE_ENV` | 本番実行時は `production` |

Replitで開発する場合は、機密値をSecretsに設定し、既存のWeb・APIワークフローを使用します。`PORT` とWebの `BASE_PATH` はワークフローの設定を使用します。

**パスワード、接続文字列、セッション署名キーをREADME・ソースコード・Gitへ書き込まないでください。** ローカル実行時も、環境変数は各プロセスに安全な方法で渡してください。このプロジェクトは `.env` ファイルの自動読み込みを前提としていません。

### データベースの初期化

開発用DBに接続した状態で実行します。

```bash
pnpm --filter @workspace/db run push
```

既存DBへの適用は変更内容を確認し、必要なバックアップを取得してから行ってください。このコマンドを本番DBへ無確認で実行しないでください。

### 開発サーバー

APIとWebを別々のターミナルで起動します。以下のポートはローカル実行用の例です。

```bash
# API
PORT=8080 pnpm --filter @workspace/api-server run dev
```

```bash
# Web
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/site-cashflow run dev
```

**ローカルでWebとAPIを一緒に利用する際の注意：** Webは同一オリジンの `/api` へアクセスします。現状のVite設定にAPIプロキシはないため、上記の2つを起動するだけでは接続が完結しません。リバースプロキシなどで、同じオリジンの `/api` をAPIへ、それ以外をWebへ転送してください。Replitでは既存のアーティファクトルーティングを使用します。

### 型チェック・ビルド・コード生成

```bash
# 全体の型チェック
pnpm run typecheck

# APIビルド
pnpm --filter @workspace/api-server run build

# Webビルド
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/site-cashflow run build

# OpenAPI変更後のクライアント・検証スキーマ再生成
pnpm --filter @workspace/api-spec run codegen
```

APIのビルド成果物は `artifacts/api-server/dist/`、Webは `artifacts/site-cashflow/dist/public/` に出力されます。公開時はWebの配信、APIへのルーティング、DBの準備とシークレット設定が別途必要です。

## 認証・データの注意点

- 複数ユーザー・権限管理ではなく、1つの管理用パスワードで利用する構成です。
- `ADMIN_PASSWORD` を設定すると、そのパスワードでログインします。
- 公開環境では、第三者が最初の管理者になれないよう、認証なしの初回パスワード設定を禁止しています。公開先にも必ず `ADMIN_PASSWORD` と `SESSION_SECRET` を設定してください。
- 公開先はHTTPSで配信してください。
- GitHubにpushされるのはソースコードです。**DBの登録データやSecretsは、READMEを追加してもバックアップされません。**
- CSVは記録の確認・出力用です。完全なDBバックアップや、再取り込みによる復元機能の代わりにはなりません。
- 現場の削除は関連する請求・入金・仕入・支払い記録にも影響するため、削除確認をよく確認してください。
- 資金繰りは予定されている未収・未払の動きを示すもので、銀行口座の実残高ではありません。
